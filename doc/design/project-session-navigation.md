# 项目、目录与编辑标签导航

侧栏顶部的「项目设置」按钮可选择默认本地项目，远程项目不进入候选。默认项目按稳定 ID 持久化，在侧栏列表与项目选择器中置顶并显示「默认」标识；保存失败保留窗口和原选择，取消不写入。默认变更只影响默认归属，不重命名或迁移已有会话。首次没有任何项目时创建「个人项目」；删除默认后选择下一个本地项目，若已无本地项目则创建「个人」并设为默认。

工作台侧栏顶部通过「项目｜智能体」两个文字页签切换导航视图，当前列表独占可用高度；窗口列表通过带数量的按钮展开，不再常驻分割侧栏。页签只切换导航内容，不改变正文、项目或草稿；各视图保留自己的搜索、滚动与 DOM，当前页签通过宿主工作台布局持久化。键盘左右方向键与 Home/End 可切换页签。

智能体视图首次选中才读取现有配置服务；配置变化在隐藏时只标脏，重新显示后更新。名称、说明和来源可过滤。本地项按明确当前项目 → 智能体默认项目 → 个人项目打开既有草稿并选择智能体，保留正文与附件，不创建正式会话或自动发送。点击「…」在工作台打开配置标签，不切换工具箱；远程项沿用同一工作台详情和项目入口。创建和编辑复用原资源服务与编辑器，不复制配置定义。

智能体配置页提供「开始聊天」操作，手机缩短为「聊天」。编辑器先完成 Agent 配置与宿主项目偏好的保存，再通过宿主 `EditorOptions.onStartConversation` 打开同一草稿入口；保存或启动失败保留配置并显示具体原因。电脑入口位于固定身份页头右侧；手机通过 `mountCompactNavigation` 合并返回、名称、聊天及窗口入口，身份表单放入基本页，保留唯一活动面板滚动。首次打开配置时选中智能体视图；查看该智能体的会话时切换到项目视图。

智能体默认项目是宿主 UI 文档中的个人启动偏好，按智能体 ID 独立保存，不进入通用 Agent 定义；本地智能体只能选择本地项目，远程 harness 只能选择同一连接下的远程项目。「查看会话」切换到该项目并按创建来源过滤会话，文件和收藏夹保持完整，可清除筛选。筛选属于当前工作台观察实例，后端在分页前执行，会话搜索也使用同一来源条件；旧会话没有来源记录时不按当前轮智能体猜测。

本地和远程项目均提供固定的「新会话」虚拟文件。草稿工具栏在「对话/执行」前显示项目选择；切换先保存当前草稿，再打开目标项目自己的草稿，不移动或覆盖正文。正式会话中不显示项目和已固定模式的选择器。通过输入区切换项目时捕获当前输入偏好，目标草稿按自身可用智能体与连接重新校验，继承有效的智能体、连接、模型档位、模式和通用生成设置；无效选择保留目标有效值，不迁移文字、附件、执行锁或 Flow 引用。远程草稿只列出当前项目可创建的远程 harness，无候选时禁止发送，后端也拒绝把远程项目草稿转成本地会话；本地草稿只列本地智能体。远程会话创建后保持原生 harness 绑定。

窗口搜索按已有窗口的名称、项目与目录过滤；电脑和手机使用同一份弹层列表，关闭弹层保留查询并将焦点交回发起按钮，不重建编辑器。固定窗口仍受关闭保护，批量选择仅作用于匹配项。

状态：单侧栏与编辑标签已实现；2026-10-17 统一本地与远程会话的列表呈现及更多菜单。实现契约见 [Session 浏览投影](vfs-session-browser.md)。超大列表窗口渲染、显式引用父历史和递归删除仍是后续能力。

## 1. 目标与决定

组件内部样式由 vfs-ui 维护，项目标题栏仅负责宿主布局。范围选择器自带样式，导入导出使用 `toolbarOptions.variant: 'plain'`；尺寸与主题通过公开 CSS 变量传入。通用文件侧栏继续保留创建文件/目录按钮，项目导航的动作可见性由项目配置决定。

项目收纳文件和会话。进入项目后复用当前侧栏，切换为项目内部导航；顶部单个项目选择器复用 vfs-ui 的 `ScopeSelector`（统一异步切换、禁用、错误处理与当前值回退），包含当前项目、“所有项目”和“新建项目…”入口，旁边仅保留新会话与项目更多菜单图标；文件通过目录树入口访问，项目内的导入导出收进更多菜单，“所有项目”视图保留导入导出工具栏。两处复用 vfs-ui 的同一份动作定义、SVG 图标与异步执行边界，项目业务由宿主注入。文件目录、会话导航与主区域的标签保持稳定，不新增横向文件侧栏。

项目文件的详细列表显示完整名称和扩展名，名称允许换行；表格固定显示名称、大小、修改时间和类型，不提供底部显示列入口；文件名悬停显示完整名称、创建时间与修改时间，大小使用易读单位，悬停显示精确字节数。目录详情、编辑标签和已打开列表复用资源浏览的类型图标、自定义图标及主题颜色。目录标题优先使用资源标题，再使用真实名称；路径显示已解码的项目名与目录层级，隐藏内部路由标记。列标题支持排序，列边界支持拖动或键盘调整宽度。编辑器标题的扩展名解析、连续重命名后的保存路径仍遵循真实文件名。

会话的主工作目录由所属项目确定，目录设置仅供查看，项目文件按原权限读写。会话可管理额外挂载，但不能将其设为主工作目录。Web/Tauri 共用应用服务校验；旧会话保留原设置能力。跨项目移动尚未恢复。

## 2. 桌面结构

```text
一个侧栏                         主区域
[项目｜智能体] [窗口数量]          [目录列表] [文件 A] [会话 B]
当前视图搜索与操作                当前列表、文件编辑器或会话正文
项目资源或智能体列表
```

- 导航视图互斥显示，各自保留搜索与滚动；窗口按钮打开独立列表。侧栏右边界继续支持拖动和键盘调整宽度，尺寸与所选页签由宿主保存。手机列表全屏显示，打开资源后切换为正文详情，返回时恢复列表状态。
- 点击项目进入该项目范围；点击目录在主区域显示直属子目录和文件。侧栏同时展示目录与文件，文件可直接打开；宽列表提供完整名称、元信息与类型图标。收藏和会话快捷入口保留。
- 单击文件打开临时预览标签；双击标签标题或“保持打开”转为普通标签。实际修改立即保留，自动保存后继续保持打开。固定标签排在普通标签前，“关闭已保存标签”跳过固定项与未保存项。
- 文件、目录列表和会话共用主区域标签。进入文件时保留来源目录标签，返回时恢复筛选、排序、列宽与滚动；重新访问目录刷新元数据。会话标签保持打开，同一会话切换分支时重新装配其编辑器。
- 标签切换保留编辑器实例、DOM、光标和撤销历史。关闭与工作区隐藏先刷新待保存内容，失败保留资源；关闭会话视图不会停止 Kernel 任务。
- 后台文件重命名更新标签身份、真实保存路径与标题；选中该标签时才更新地址。恢复已关闭标签与键盘标签切换可用于找回当前工作。
- 本地和远程会话均在左侧项目列表直接显示，按最近活动排序，并展示创建/修改时间；本地关联会话保留父会话说明，不再默认隐藏后代。每个会话保留独立正文、历史、草稿及附件，不增加横向辅助列。
- 导航保存到原有浏览状态文档；侧栏布局与保持打开/固定标签保存到宿主 `etc:/ui/<scope>.workbench.json`。恢复标签先建立入口，点击时才读取内容；预览标签不持久化，文件内容不写入 UI 状态。

小屏本地/远程会话与新建草稿使用同一排导航：左侧返回列表，中间显示标题和所属项目，已打开图标开启顶部弹层；隐藏重复的返回行、标签行和项目说明。宿主通过 mountCompactNavigation 挂载，编辑器公开 data-editor-mobile-navigation 标记；普通文档保留独立返回入口。已打开面板使用现有列表及编辑器实例，保留固定、批量关闭和草稿；关闭后列表归还侧栏。宿主将活动工作区和焦点同步到 body[data-mobile-navigation]，不依赖 CSS :has()；隐藏标签和非活动工作区不影响全局导航。小屏会话正文持续收起全局底部导航，返回列表恢复，不随滚动或输入失焦反复切换；列表页导航高 56px、按钮点按高度 48px，正文保留底部安全区。其他编辑器仍在输入时收起导航；可视视口改变时调整应用高度。输入从一行增长，限高后内部滚动，不持续压缩消息历史；历史仅在原本贴底时随高度变化跟随。

## 3. 创建与整理

| 入口/动作 | 结果 |
| --- | --- |
| 项目抽屉“+ 新会话” | 打开该项目的固定草稿入口，首次有效提交后转为顶层会话 |
| 正文标题栏更多菜单“新建关联会话” | 在当前会话下创建独立空会话并打开；明确不继承历史 |
| 会话行更多菜单“新建关联会话” | 明确以该行会话为父，不依赖其他区域的选中状态 |
| “移到其他会话下…” | 搜索选择同项目内的目标父会话，连同当前会话的后代一起移动 |
| “移到项目顶层” | 清除当前会话的父关系；其后代随它成为新的一组 |
| 重命名 | 原地修改名称，不改变 ID、父关系或正文 |
| 删除当前会话 | 明确提示只删除此会话；直接子会话提升到被删会话的父级，后代保留 |

新建后直接进入可输入的项目草稿，标题固定为「新会话」，无需先填写创建弹窗。草稿有独立身份；首次有效提交转正时保留该身份，再补建另一份新身份的草稿。正式会话允许重命名，名称变化不改变身份。创建中的按钮防止重复提交，失败时保留原会话和草稿。

本地、远程和智能体快捷入口共用项目草稿：每个项目仅有一个当前 UUID，切换项目读取各自内容和附件，切换智能体只更新选择。UUID、标题和路由各有职责；转正只更新当前标签的路由、标题、图标与状态，不关闭再打开编辑器。外层草稿编辑器接管正式控制器，保留输入框、历史容器、焦点和提交等待期间的新输入；正式能力（搜索、导航和消息操作）继续委托对应控制器。接纳后项目与对话/执行选择同时隐藏，后台确认不抢回其他活动标签。

本地 prepare 沿用草稿 UUID 物化 Session，并由宿主初始化 Kernel；持久 Round 的对应 submission/execution 证据才触发转正。远程草稿使用 UUID 隔离创建/提交 journal，native create 不构成转正；首次 turn 确认且没有待核对操作时，在同一事务写入提升记录、原生引用到 UUID 的索引及下一份草稿。引用按项目、连接、授权主体、profile 和 native session 隔离；重新打开沿用同一 UUID journal，保留输入和未知操作核对记录，原生 ID 仍由服务端分配。unknown 不自动重新提交。丢弃草稿会分配新的 UUID，并同步当前标签的草稿身份。

回归：`ui/app-shell/tests/draft-promotion.test.ts` 覆盖原地转正、首次提交及后续回复在已挂载历史区显示、初始化失败重试、隐藏确认、项目切换、丢弃后提交及另一视图接纳；`ui/app-shell/tests/remote-session-workbench.test.ts` 使用真实编辑器验证远程原地转正和重开恢复；`backend/app-core/tests/remote-project-draft.test.ts` 验证持久确认与授权隔离。


创建入口区分“新会话”和“新建关联会话”，不提供根据焦点暗中改变行为的通用加号。常用入口只有项目的新会话；关联创建、会话时间、重命名、移动、归属信息及删除收进正文共用更多菜单。会话时间在菜单内折叠，创建关联会话的说明明确独立历史与共享项目文件。拖拽可以后续补充，所有整理操作必须能通过菜单完成。

首版不提供一键递归删除整组。批量删除沿用明确选择的会话集合，确认框展示数量及保留后代的处理方式，不能把未选择的后代隐式加入删除集合。

### 目录如何共存

保留已有项目分组和会话目录。项目分组收纳项目，项目内部的会话目录收纳顶层会话；子会话通过父关系归属，随顶层会话一起移动目录。新建流程不要求先建目录，也不在每个子会话下再增加会话目录。

旧目录及现有会话完整保留，不自动移动或转换为父子关系。项目内搜索应能直接命中目录深处的顶层会话和子会话，并展示所在项目、目录和父会话；打开结果直接到正文并同步侧栏，不要求先逐层展开目录。

### 统一工具栏与数据交换

- 项目创建进入项目选择器；目录行的新建文件/目录图标在悬停或键盘聚焦时显示，触屏持续显示。项目顶部在项目选择器旁同一行排列文件、新会话、导入和导出图标；导入/导出复用资源浏览原有工具栏的选择上下文、权限和执行逻辑，不另占搜索栏下方的一行。
- 资源浏览中可写物理目录行在悬停或键盘聚焦时提供新建图标，目标是对应目录；目录详情的新建图标位于上一级和刷新之后的工具栏，目标是当前目录，子目录内容行不显示新建图标，只读目录页面隐藏新建入口；资源浏览行的新建控件排列在收藏之前；使用原有应用文件系统与权限校验；文件行的操作菜单复用 vfs-ui 行策略与命令，不另写授权逻辑。
- 目录列表支持全选当前筛选结果、取消选择、批量删除和移动。选择在排序及筛选时保留，删除使用原有确认，移动使用原有目标目录选择器；只读、固定入口和宿主菜单限制由 vfs-ui 统一校验。会话创建和子会话创建使用明确的宿主入口。
- 已打开列表提供关闭、Pin、全选及关闭所选。批量关闭保留固定标签，保存失败的标签保留并提示，其他标签继续关闭。
- JSON 格式为 `itookit.workbench` version 1，入口见 `app-core/src/projects/workbench-archive.ts` 与 `workbench-import.ts`。`items` 支持 `project`、`group`、`session`、`files`；项目/分组/会话通过 `children` 表达组织关系，文件以相对路径和 Base64 内容表达。
- 项目文件包含隐藏文件、SeqFile 记录、文件关联资源；会话包含历史、草稿、设置、分支索引及嵌套附件。也接受已有的 `itookit.session` v2 和旧版会话 JSON。
- 导入前验证整个归档。项目导入到当前项目所在分组，会话导入到选定项目/会话目录，文件导入到选定文件的父目录或选定目录。始终创建新副本，同名项目/目录/文件加数字后缀；导入失败回收本次已创建的内容，清理失败显式报错。
- 导入的项目使用新的托管目录，不照搬导出机器的绝对路径和挂载授权；会话 ID、存储修订及更新时间按本地新记录生成。归档保存用户内容和组织关系，不恢复正在运行的 Kernel 任务或外部进程。

## 4. 上下文与文件

每个子会话有独立 ID、历史、分支、草稿、任务及附件。父子关系只表达收纳，不触发执行，也不自动拼接祖先聊天历史。

新子会话默认按所属项目的新会话规则初始化，可以访问该项目已授权的共享文件。父会话额外授权的目录、运行态及临时上下文不因父关系自动继承。项目仍只有一个常用文件入口，会话附件及特殊挂载放在会话的更多菜单中。

输入区提示当前接收会话及独立历史状态；已有初始材料可在正文上方折叠查看。更多菜单的“带初始材料新建子会话”允许显式选择父会话内容并预览，创建时保存不可变 `initialContext`，后续不持续继承父历史。标题栏提供“同组会话”切换入口，不默认复制全部历史。既有聊天分支继续表达同一会话内部的历史分叉，子会话使用独立的关系字段。

## 5. 窄屏与键盘

手机保留“项目抽屉”和“正文”两个主要界面。从抽屉点会话直接到正文，子会话切换使用正文标题的“同组会话”面板，选择后关闭面板。面板可以直接选择任何后代，不添加按深度累计的页面。

正文返回按钮回到项目抽屉并恢复滚动位置；“属于：父会话”用于切父会话，二者明确区分。浏览器后退仍按实际访问历史回放，不强行改为父级导航。文件入口直接显示文件列表，打开文件后可以返回文件列表。

抽屉标题提供 `aria-expanded`，会话选择提供当前项语义，所有按钮可用键盘触达。切换面板打开时聚焦当前会话，关闭后归还触发按钮；Escape 关闭临时面板。新建会话后聚焦输入框。

## 6. 数据与组件边界

Session 元信息增加可选 `parentSessionId`，缺省或 null 表示顶层会话。继续使用独立 Session 的既有物理存储路径，项目文件目录、MindOS profile 根目录均无需搬迁。不要把该字段写入历史索引。

约束：

1. 父会话必须存在，且与子会话属于同一项目；不能指向自己或任何后代。
2. 一棵会话树共享顶层会话的目录归属。更换父会话跨目录时，同事务更新整棵待移动子树的父引用和目录字段；同目录重组仅更新必要的父引用。
3. 父关系和目录归属通过专门的操作验证，不能被普通标题/草稿更新绕过。并发改变归属时在提交前重验关系，不能只依赖界面禁用目标。应用运行时为结构修改取得受影响会话的写租约；拒租时不写入关系。
4. 不持久化第二份 children 或 rootSessionId 权威数据；从摘要构建父子索引并缓存，避免多份关系互相矛盾。对持久化修改做一致性通知。
5. 旧数据没有父字段时全部按原位置的顶层会话显示。缺失父引用、循环或跨项目损坏关系必须能在恢复入口看到有关会话，不允许投影无限递归或静默隐藏；正常写入拒绝这些关系。
6. 会话资源身份继续以 Session ID 为准，父关系不能编码成必须逐级解析的新 URL。旧目录限定链接继续兼容；父关系改变不改会话 ID，重命名不改链接。
7. 单独导入会话默认成为目标目录的顶层会话，不照搬可能指向本地无关会话的父 ID。整组导入为每个成员创建新 ID，按归档中的父子结构重建引用。

职责划分：

| 层 | 职责 |
| --- | --- |
| `llm-session` | 持久化父引用、关系事务、独立历史及草稿 |
| `app-core` | 项目边界校验、会话树查询/变更、创建与删除生命周期、浏览投影 |
| `app-shell` | 项目抽屉、全部会话列表、宿主更多菜单、创建目标、路由及窄屏行为 |
| `vfs-ui` | 列表投影、目录展开、搜索/选择/键盘与外部详情行的菜单复用 |
| `llm-ui` | 聊天正文与共用标题栏，通过 mountMoreMenu 挂载宿主动作并在销毁时清理 |

Web 和 Tauri 使用同一套宿主逻辑。侧栏、详情列表与标签资源由 app-shell 装配；vfs-ui 不需要认识 Session 父子业务。

### 删除与失败恢复

已有删除流程会先关闭执行，再删除 Kernel 和 Session 存储；物理文件删除不能与关系元数据天然形成单个原子事务。实现使用 `folders.seq` 中的删除意图连接这些步骤，不把关系元数据事务当作物理删除事务。

停止失败时不删除正文或改变父关系。停止成功后，在同一事务中记录原父关系、直接子会话集合并完成关系提升，然后删除 Kernel 与 Session 存储，最后清除意图。物理删除失败时已提升的孩子仍然可见，重新执行不会重复改变归属；启动在取得待删会话租约后重试清理，并排除其执行恢复。待删除会话禁止再挂入新子会话，并发关系操作须重验状态。发生后续清理失败时保留明确的可重试状态，项目导航提供“继续清理”入口；未删子会话始终能从导航访问。

首版删除保留后代。递归删除作为后续独立能力，避免用“一个目录递归删除”替代多个独立会话的生命周期管理。

## 7. 实现范围与验收

1. 先补父子模型和操作约束，覆盖创建、循环拒绝、同项目移动、提升、旧数据读取、独立历史/草稿及删除故障恢复。
2. 项目抽屉固定文件首项，隐藏内部 `@sessions` 容器；直接展示全部会话及父关系。保留已有分组目录。
3. 在共用更多菜单接入关联创建、同组选择及归属动作，更新现有工作台测试；不混用聊天分支。
4. 验证窄屏、键盘、浏览器回放、刷新恢复及 Web/Tauri 共用行为；最后移除旧会话/文件 tab 所造成的重复入口。

关键验收场景：

- A → B → C → D 连续创建：侧栏直接展示四个会话并保留父关系说明；A 与 D 相互切换只需一次选择。
- 打开 B 后仍能直接看见并选择 A、C、D；新建 B 的子会话时不清空其草稿。
- 删除 B 后 C 提升到 A 下，D 仍属于 C；遇到停止失败或清理中断，未删除会话可见且能恢复处理。
- 把 B 移到顶层后，C、D 跟随 B；侧栏父关系说明更新，正文保持 B。
- 跨项目移动、把 A 移到 D 下、与删除并发挂入子会话均被拒绝，持久化后没有循环或悬空引用。
- 打开旧链接、中文项目名和刷新深层会话都能直接恢复正文，物理目录不发生迁移。
- 项目只有一个常用文件入口；会话列表加载不枚举全部任务、附件或聊天历史。
- 手机从项目抽屉直接进入 D；切到 A 只打开一次同组面板，不连续返回三层。


实现证据：`backend/llm-session/__tests__/session-relations.test.ts` 覆盖独立历史、重开、循环与跨项目拒绝、子树移动、提升、删除故障重试及并发关系变更；`backend/app-core/tests/session-family.test.ts` 覆盖损坏关系投影和 IndexedDB 重启删除恢复；`ui/app-shell/tests/project-workbench-ui.test.ts` 使用真实 VFS UI 验证项目文件、保留目录、多代同组切换。

当前范围：单侧栏有搜索与可滚动成员，关联会话直接可见。删除保留后代，父会话专用授权不继承。会话运行状态汇总、超大列表窗口渲染和快速定位按钮仍待后续完善，不作为本次已完成能力。

## 会话信息、活动排序与抽屉预览

- 正文标题栏的共用更多菜单提供折叠的“会话信息”、关联创建、重命名、移动、提升和删除。时间使用会话持久记录；最后活动包含内容、分支、会话信息和草稿变化，滚动、折叠和历史可见性设置不更新时间。
- 归属操作在所有宽度均保留在更多菜单；聊天工具栏达到 760px 时外显刷新、重新运行和复制，窄屏移回菜单。宿主通过 EditorOptions.mountMoreMenu 挂载资源动作，编辑器负责菜单开关和释放；无独立组织工具栏。
- 项目会话按 lastModified 倒序，同时间用 ID 稳定排序，文件入口保持在会话之前。
- 已进入项目的目录/会话列表直接使用导航区的可滚动空间，不再把项目卡片及文件辅助列并排展示。

Markdown 文档间的相对链接以当前文档目录解析，通过宿主文件导航映射为项目或会话文件路径，不使用浏览器页面 URL 或收藏夹路径。链接携带的章节锚点在目标编辑器就绪后定位。

正文与导航有独立生命周期。显式文件/会话恢复不等待目录：backend.workbenchView(initialNavigation=false) 跳过目录和项目组织预读；普通文件直接按路径读取正文与 revision。侧栏仅在活动工作区且实际可见时加载，手机正文期间不读取隐藏目录或观察其他标签所属项目；返回列表后读取最新目录，错误局部重试。未打开工作区不自动构造或预热。已打开编辑器保留 DOM、草稿、光标与撤销历史，隐藏会话只暂停观察和面板轮询，任务继续由后端执行。

文件编辑恢复副本与后端保存分开：sessionStorage 保存小文本，IndexedDB 保存大文本，按浏览器标签页和资源身份隔离；当前文件打开时只查自身记录。正文一致且权限允许时恢复未保存编辑并保持 dirty；原文摘要或权限不匹配时保留独立副本并暂时只读，不能自动覆盖后端。保存成功确认后清除，保存结果未知时先核对后端正文；本地存储失败保留页面并保护未完成退出。正常加载与重连不显示 banner。

桌面项目归属与标签资源名同行，以独立只读 context 显示；重命名只提交资源 title。移动端以标签打开状态和激活代次表达导航意图，不用正文 DOM 暂时为空推导返回列表；显式深链直接进入正文，加载结束后仍保留用户主动返回列表的选择。

内部 @sessions 容器的成员通过 VFSUIShell.loadDirectory 独立加载到单侧栏投影，避免依赖某个浏览器的展开偏好，也不触发兄弟文件目录的手风琴收起。HTTP 手动刷新先等待导航缓存失效，再读取侧栏。每个浏览器会话运行上下文都绑定草稿提交收尾；旧草稿刷新先核对该项目的持久提交证据，补偿漏通知或临时提升失败，再凭提升回执申请新 composer。未提交的 Round 不触发提升；并发刷新只生成一份后继草稿，旧写游标继续拒绝跨代保存，未保存输入不能被后台通知替换。

## 后端导航与视图生命周期

项目选择、会话归属、离线状态、删除待办与透明分组的加载路径由 `ProjectService.navigation` 聚合。前端仅按返回路径加载，并按 `navigationTransparent` 元数据呈现分组内容；内部目录名不再进入 UI 展示判断。旧会话路径、深链和收藏身份保持兼容。刷新先等待异步导航失效确认，再更新可见列表；ViewRefresh 合并变更并在隐藏期间保留标脏，任务详情及分页由 SessionTaskView 独立管理。

从文件发起聊天时，前端排版引用后调用 `createSessionDraft`；后端解析来源项目并原子提交会话身份与初始输入，成功后前端才导航。未保存正文与断线恢复副本继续由前端持有。

### 草稿提交与恢复边界

`app-core/projects/drafts` 拥有草稿转正策略。远程打开原生控制器前，先以 SeqFile 事务固定提交身份和 `remoteTarget`（连接、服务器项目、授权主体、规范 profile）；并发准备同一目标复用提交身份，其他目标冲突。后续输入保存只修改 `data`，不会重定向已准备操作。恢复优先读取该固定目标，旧远程待核对日志在打开时补齐目标；原生请求仍由 Harness journal 保存 requestId 并查询回执，不自动重发。

远程结果未知时拒绝丢弃草稿。确认首个 turn 后，当前草稿、提升回执、原生身份到 UI UUID 的映射在同一事务更新，并分配后继草稿；执行失败不撤销已接纳会话。创建来源与用户当前选择的智能体保持分开。

UI 的 `SessionDraftMaterialization.createEditor` 显式传入稳定输入区的控制器创建能力，宿主只准备文件及观察资源，不通过模块全局 WeakMap 查找 DOM 所有者。转正保持文字、附件和焦点，同时应用后端已固定的执行模式；附件交互按当前能力判断，不以首次渲染时的能力永久决定监听。

# 数字分身：规则驱动设计与实施

## 产品目标

数字分身是个人信息平台的持续更新视图。自动发现所有已登记项目的文本文档、原生会话和可读取的远程 harness 会话，用户通过扫描规则控制范围，不维护逐个来源的授权清单。

流程：项目目录与会话目录 → 规则筛选 → 周期更新 → 模型提取 → 分身画像、记忆与目标。

导航入口为“数字分身”，包含总览、人物与关联、记忆、目标、自动更新。总览优先展示最近了解的信息；自动更新直接展示扫描规则，运行记录与来源明细折叠。工具箱继续配置模型、Agent 与 Flow。

## 用户配置

单用户配置以规则为中心。“通用设置与全局忽略”默认展开，显示提取模型、用户姓名、别名/邮箱、提示词、全局排除、暂停分析和允许会话使用相关知识；“模型与用量”统一展示模型连接、累计已用 token、待结算 token 和预算；个人信息与分析范围分区展示，提示词折叠查看。首次使用应用默认模型；首次启动尚未配置模型时，后续检查会补取默认模型。模型和预算不在每条规则中重复配置。通用设置按字段自动保存：模型选择与开关立即提交，姓名、别名、全局忽略与预算输入防抖 450 ms 后提交；保存状态在设置卡片显示，失败保留输入并提供重试。写入串行执行并读取最新 settings revision，只提交变更字段，避免覆盖后台预算记账和其他设置；导航及关闭工作台前等待待保存修改，失败时保留当前页面。规则新建和编辑仍显式保存。

规则配置名称、启停、扫描范围、自然语言关注点（可选，最多 2000 字符）、忽略规则和更新周期；提取类型放在高级选项。关注点决定从正文中提取什么，不是正文脱敏规则；忽略规则决定哪些资料不读取。默认周期 30 分钟、全部类型。应用启动和 CLI 扫描启动会初始化存储，无需先打开页面。在有可用默认模型且没有自动规则时，首次建立一个邮件默认规则（邮件工作区内的受支持文档及项目内 `.email` 文件），工作台、记忆卡片、笔记和会话不再自动纳入；此初始化幂等，用户删除规则后不会再次自动创建。

新规则保存即声明其扫描范围，无需逐个添加来源或重复勾选授权。匹配预览返回匹配和排除的已发现资源（`resources` / `excluded`），不读取正文或调用模型，也不新增来源记录。内置跳过的目录不会出现在发现结果中。

全局忽略对所有规则与后续知识使用生效，已提取记录保留但不继续注入上下文；规则内忽略仅约束本规则，另一规则仍可包含该来源。忽略、暂停与删除知识是不同操作。

文件、目录、本地 Session 与远程 harness Session 的右键“数字分析”打开统一对话框，可选择所有、画像、人物关系、项目与决策、事件、目标与承诺。保存时持久化显式规则并立即请求后台扫描，不等待发现或模型结果；后续每 30 分钟更新，仍遵守全局暂停、忽略和预算。对话框订阅状态，显示来源进度、任务错误、提取知识和原文证据。目录递归选择，不按同名跨项目匹配；文件名中的通配符作为字面量编码。

“移除分身”将来源范围加入全局忽略，停止对应任务，删除该范围来源提取的非独立知识与证据，图谱随之更新；原始文件、邮件、会话及用户独立声明保留。保留已禁用的来源定位记录并更换 incarnation、清空进度，显式重新加入时可以重新提取；迟到结果不能恢复已移除信息。普通规则停用与此删除操作不同。

提取任务显式设置 thinking=false、maxTokens=8192、stream=false，避免兼容服务默认思考耗尽正文额度；通过提示词约束 JSON 并在解析阶段严格校验，不向不支持 json_object 的协议发送该参数。诊断日志分别记录正文/思考字符数、结束原因和模型用量。提取提示词要求 JSON 原子事实和精确原文证据，限制最多 10 条、区分用户/第三方和建议/决定，明确关系才建立关联。用户姓名及最多 20 个别名/邮箱作为身份数据随任务冻结；文档或邮件中明确指向该身份时可标注 self，同名歧义不自动认定。发送与提交核对身份是否改变。页面展示通用实际提示词，规则关注点和类型限制在具体任务中追加。

### 匹配语法

白名单和黑名单分别维护，每行一条；空白和以 `#` 开头的注释被忽略。`local:/home/me/private/` 和 `remote:/archive/` 按实际目录路径或项目内路径忽略本地/远程文件，嵌套远程挂载按最长挂载点识别。`session-name:私人*` 匹配本地及远程会话名称；`session:` 兼容原 ID 范围匹配，也支持名称。

```text
# 白名单示例；留空表示全部受支持资源
project:Alpha
file:**/*.md
file:docs/
session:native/**
session:harness/codex/**
session-name:工作*

# 忽略规则示例
*.log
drafts/
/private/
project:Archived*
file:**/drafts/**
session:harness/codex/temporary-*
```

| 前缀 | 匹配对象 |
| --- | --- |
| project: | 项目稳定标识或名称；命中该项目的文档和会话 |
| file: | 相对项目根目录的文件路径，使用 `/`，没有开头 `/` |
| session:native/ | 原生会话稳定标识 |
| session:harness/ | harness profile 标识 / 会话稳定标识 |

无前缀模式用于文件路径：`*.log` 匹配任意层级日志，`drafts/` 匹配任意层级该目录，`/drafts/` 只匹配项目根目录，含中间斜杠的 `docs/drafts/` 从项目根匹配。带 `file:` 的已有模式保持根目录相对语义。

支持 `*`（不跨目录）、`**`（跨目录）、`?`（单个非 `/` 字符）、目录末尾 `/` 和整行注释。`**/*.md` 同时匹配根目录和子目录。采用大小写敏感匹配；这是借鉴 gitignore 的受限语法，不支持 `!`、字符集合、花括号或转义，避免白名单/黑名单再引入反转顺序。

一条规则内：白名单为空或任一命中，且黑名单没有命中，即允许扫描。普通规则取并集；右键创建的显式选择按最具体的来源范围优先决定提取类型，避免“画像”被宽泛的“所有类型”覆盖；某条规则的黑名单不会阻止其他规则允许该资源。全局排除对所有规则生效。名称规则随项目改名重新匹配，稳定 ID 规则保持身份；预览显示项目名称和 ID，便于检查范围。

内置跳过隐藏路径、`node_modules`、私密标签和受保护文件，不把配置、分身产物和内部执行快照当作个人资料。

## 自动更新

项目服务负责项目身份与目录授权，分身只通过其公开接口枚举和读取。项目目录读取使用 `ProjectService.openFiles`，涵盖应用内、已登记宿主目录和远程项目；不直接读取 IndexedDB/SQLite 或任意宿主磁盘。

原生会话通过 SessionRepository 和当前分支 RoundLog 读取，未归属项目的原生会话归入 `@unassigned`。内部 `twin-analysis-*` 会话不参与发现。正在运行、内部 exposure、合并历史或不完整历史保持不可用，不猜测缺失正文。

远程 harness 通过已有项目客户端枚举有历史能力的 profile，分页读取活动及归档会话。读取历史不恢复执行。仅提取可见 userMessage/agentMessage 文本；系统提示、推理、工具输出和审批内容不进入来源正文。会话正在执行或历史不可读取时等待下次周期。

| 来源变化 | 处理 |
| --- | --- |
| 新项目、新文件、新会话 | 下一次到期发现，匹配规则后自动加入 |
| 正文变化 | 内容 hash/来源代次变化，旧证据退出有效分身，从新版本重新提取 |
| 同路径替换 | 可观测原生身份或 hash 变化时建立新代次，不沿用旧证据 |
| 删除 | 仅在完整成功枚举该范围或确认来源不存在后判定；依赖该来源的旧信息失效 |
| 离线或枚举失败 | 标为不可访问并显示诊断，不判定删除，恢复后重新读取 |
| 规则停用、删除或范围变化 | 按所有仍启用规则重算来源；没有规则允许的来源停止更新、保留最后一次有效快照，并在记忆中标注停止更新；已删除或不可访问的来源仍不作为有效证据 |
| 全局排除 | 所有规则都停止使用该来源，拒绝在途旧结果 |
| 移动或改名 | 原生会话稳定 ID 可沿用；文件没有跨移动稳定身份时按旧路径退出、新路径发现处理 |

文件到期更新校验正文 hash，避免仅靠时间戳漏掉保留元数据的内容替换；普通界面/使用核对可用元数据跳过重复正文读取。未变化版本不重复模型提取。文件的原生身份仍由目录绑定、路径和可观测创建时间组成，不宣称可识别所有保留元数据且同内容的宿主替换。原生与 harness 会话周期读取可见历史并比对 hash；当前不实现跨轮编辑的精细片段依赖。

来源删除、替换、全局排除后，自动信息保留必要历史但不再计入有效画像或模型检索。用户手工记录与纠正为独立陈述，不随原始来源失效。有明确主体和原文证据的信息自动生效，主体为 `unknown` 的候选待确认；来源中的同名人物不自动合并。模型提取仍可能出错，用户可纠正、争议、拒绝或遗忘；自动生效不代表完成了语义正确性验证。

## 实体画像与局部关联

[graph.ts](../../packages/app-core/src/digital-twin/graph.ts) 从有效记忆派生人物、组织、项目、事件及目标节点。图节点与边都引用记忆 ID；记忆保留来源与原文证据，因此争议、来源失效或遗忘会立即反映到图中，不另外保存一份可能残留的图正文。

模型可输出可选 `relation: {predicate, target, targetKind}`，其中目标类型为人物、组织或项目，必须有原文支持。主体与项目、事件的共同背景用“相关背景”边表达，不推断负责、参与或因果关系。项目名明确匹配所在项目 ID/名称时采用其稳定 ID；其他项目标签仍存在名称歧义，尚无通用项目身份消歧。

新提取人物身份使用来源 ID、可观测原生身份 hash 和来源内标签，普通正文修改不改变人物 ID；替换来源的原生身份改变时建立新身份。旧条目保持原身份，不猜测迁移。`mergePeople` 允许用户合并两个非 self 人物，身份映射保存到既有 `entity` 记录族并通过共享版本检查点防止并发形成循环；原始事实和证据不改写。尚不自动判断跨文档别名，也不生成无证据的人格画像。

“人物与关联”采用对象列表、对象详情、按记录时间排列的证据和局部 SVG 图；图上最多显示 12 个直接邻居，下方列出全部关系。点击节点切换中心，点击事实的纠正入口定位到记忆编辑。事实与关系可手工更正。检索先过滤未被全局忽略的有效记忆，再沿显式名称匹配的实体扩展一跳，与关键词分数合并，最多返回 5 条；不使用被忽略或已失效的来源填充关联上下文。

## 调度与存储

复用现有扫描队列和 Kernel 提取任务，默认串行。每 15 秒检查到期规则，按配置周期发现与处理资源；错过的触发合并补跑。相同来源版本、模型目的地、提取类型和关注点复用进度；更改关注点或配置的用户身份会独立提取，旧的无关注点检查点保持兼容。运行冻结关注点并在发送/提交时校验，不因规则重叠重复提取。

运行时在线才调度：浏览器/桌面关闭、休眠或后台节流会延迟更新。CLI `twin watch` 可作为持续在线进程；未安装独立操作系统服务。

保留的内部机制只有必要的来源身份/hash、提取进度、执行引用、预算记账和扫描宿主租约。规则编辑、停用、全局排除、模型切换和删除均在模型发送及结果提交时重新校验，阻止旧任务写回。预算预留和实际费用原子记账；未知模型用量不按免费释放。设置 `budgetUnlimited: true` 时取消累计总预算及自动规则运行额度检查，但继续预留和结算用量；关闭后恢复保存的 tokenLimit，缺失该标记的旧记录按有限预算处理，0 仍表示没有可用预算。旧指定来源计划的独立运行额度保持有效。预算与用量为启用以来的累计值，不按月归零，也不按模型连接拆分。

仍使用 VFS 公开 SeqFile 事务，不新建数据库表。四个文件位于 `/var/lib/digital-twin/personal/`：

| 文件 | 内容 |
| --- | --- |
| authority.seq | 分身身份、遗忘代次、tombstone 和清理状态 |
| knowledge.seq | 所有领域记录的版本链与当前指针，包括记忆、来源、规则、运行与设置；旧 grant 记录保留但不再作为使用门禁 |
| processing.seq | 提交/遗忘/清理的操作回执 |
| indexes.seq | 固定分页索引与族索引 |

实际记录族的文件归属以 [SeqTwinStore](../../packages/app-core/src/digital-twin/seq-twin-store.ts) 为准。当前 schema 1/layout 4；已知 layout 2/3 事务升级元数据并保留身份、记忆和遗忘状态，阻断旧客户端忽略规则授权。未知布局保持拒绝，不清空重建。

旧指定来源计划与 CLI 命令保留兼容，旧计划保持原范围；新默认规则仅覆盖邮件。旧版本未经用户修改的 `Default` 全范围规则一次性收窄为邮件，用户自定义或修改过的规则保留。界面编辑旧计划后转换为自动规则。新规则通过 `rules` 标识，持久 sourceIds 为空，每次运行从自动来源索引解析其范围。

公开新入口为 `saveScanRule`、`previewScanRule`；启停、删除与立即扫描沿用 `setScanPlanEnabled/removeScanPlan/runScanPlan`。reader 的 `discover/probe` 是平台无关端口；数据库 driver 不含分身业务。

自动读取受支持的文本文档；PDF、Office、图片等尚未接入正文解析。每来源最大 1 MiB，原生当前分支最大 2000 轮；harness 分页有游标循环与字节上界。最多 10000 来源、50 规则、100 待结束运行、500 当前记忆，运行/检查点及其他记录族各有 10000 上界；页面来源明细展示前 200 条，不限制后台处理这 200 条之外的来源。

本地原生 Chat/Agent 默认可使用相关有效知识，无需逐会话、Agent 或模型授权。提取模型与消费模型可不同。检索与发送前仅校验相关知识的来源，不重新扫描全部资料；发送前仍校验知识版本、来源状态、全局忽略及使用总开关，并保留使用回执。旧 grant 记录不再限制使用，CLI grant 命令和会话授权表单已移除。目标只关联既有执行，不自动启动行动。扫描心跳延迟且未被其他宿主接管时，按原 owner/fence 以 CAS 续租，提交前可补续租；已释放或被接管的租约不可复活，旧宿主结果仍拒绝。共享 profile 的租约依赖事务和可比较时钟；真实跨时钟、多端同步、外部备份恢复和完整进程崩溃矩阵不在本次验收内。

提取输入单块上限为 32,768 个 UTF-16 字符（不是 token），检查点仍保存原文偏移。优先在完整会话轮次结束处分块，超长轮次退到消息边界；普通文档优先段落、标题及完整 Markdown 代码围栏边界。单个片段超过上限才硬切，避免拆开 Unicode 代理对。新任务不再添加任意 256 字符重叠，旧在途任务保留原偏移与重叠恢复行为。来源序列化和 hash 不变，不因此重置已完成扫描；这不等同于轮次增量读取。预算仍按实际分块 UTF-8 字节数加关注点、用户身份及 8192 输出额度保守预留，32K 字符不保证适配所有模型上下文或剩余预算。

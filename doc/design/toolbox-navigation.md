# 工具箱导航

Web 与 Tauri 共用 `ToolboxWorkbench`，主导航中用「工具箱」集中展示流程、技能、提示词、工具、MCP、模型连接和服务商。存在工作台时，智能体使用入口移至工作台独立抽屉，配置编辑继续复用原有编辑器和资源路径；独立工具箱仍可展示智能体。

## 交互

- 一个 vfs-ui 单列列表、一处搜索、七个常驻分类筛选（全部、流程、技能、提示词、工具、MCP、模型）；筛选不会关闭正在编辑的内容。每类记住搜索词。智能体配置深链仍可进入其专属管理范围，但不出现在全部列表或常驻分类中；独立工具箱保留智能体分类。抽屉按上述类别固定排列，类别内资源按名称自然升序排列（数字按数值、中文按中文本地排序）；同名用资源路径稳定决胜，点击、刷新和使用时间不会重排。
- 每行展示类别图标、名称和用途；不重复显示类型标签。图标提供悬停提示和读屏标签，服务商优先使用用户自定义图标，内置默认图标使用 SVG 字母标识，未知服务商使用通用图标；连接统一用链环、设置用调整图标。所有资源以一层抽屉展示。原有智能体与流程目录按路径展平成抽屉名称，文件位置不变；默认目录中的条目归入「未分组」，系统提示词作为独立资源使用相同抽屉。搜索覆盖折叠抽屉中的资源。
- 共用工具栏提供新建、导入、导出和整理条目。新建对话框选择智能体、流程、技能、提示词、模型连接、服务商或 MCP；智能体、技能、流程、提示词与 MCP 可搜索选择本类已有抽屉，也可直接输入新名称，提交成功时一并建立分组。当前抽屉自动继承，取消不产生空抽屉。模型仍通过服务商分组；对应原有专用编辑器。MCP 和提示词直接打开所选资源表单，避免再套一层列表。
- 工具由运行时目录及 MCP 已发现能力提供，工具实现和参数定义保持只读；详情的使用配置可以选择智能体并保存授权。内置工具写入该智能体的 toolIds；MCP 工具写入来源连接的 mcpProfileIds，表单明确说明授权该连接全部工具。保存保留其他策略字段，不绕过宿主和项目权限。详情显示说明、参数、启用状态、来源，MCP 工具可跳转到对应连接。列表不会连接 MCP，也不会执行工具。
- 移动端沿用列表/内容切换与返回列表按钮，不增加第二层侧栏。

模型按服务商显示抽屉，第一项为设置，下面是该服务商的连接。已配置且启用、未配置、禁用、缺失服务商按组排列，组内固定按名称排序。配置状态仅指凭据是否已填写（Codex 使用本地认证），不表示联网检查成功。抽屉显示连接数和状态；新建连接默认使用当前选中的服务商，也可在对话框改选。打开资源链接会展开所属抽屉，呈现单项表单；连接可直接跳转所选服务商。

工具按文件、网页、记忆、任务、终端、协作、技能与扩展分抽屉，MCP 工具按来源服务分组。各类使用不同图标并显示工具数。通过整理条目可批量分配工具到自定义抽屉，不改变工具来源、实现或授权。抽屉使用浅色标题底、固定箭头位置及加粗名称；内容区缩进并显示细导线，选中项独立高亮。分组在「全部」和专属分类中一致，搜索自动展开匹配项，点击不会改变排序。设置页移除 Provider、Connection、MCP、系统提示词重复入口；未配置工具箱的宿主仍可使用独立设置编辑器。

抽屉右侧与条目旁的更多操作按钮支持触屏与键盘。抽屉可新建条目、重命名和删除；单项菜单「删除抽屉（保留条目）」只将内容归入「未分组」。多选删除包含抽屉时，展开抽屉全部卡片并与选中卡片去重，先按原有卡片流程删除，再移除所选抽屉；配置类卡片沿用关联影响确认，取消或失败时停止并保留抽屉，已经成功删除的卡片不回滚。「未分组」为固定分组，只清空卡片；工具引用及其抽屉不提供批量删除。条目可单独或同类多选后移动，整理弹窗支持切换类别、搜索、全选和清空。抽屉、单项和多选菜单均使用统一「导出 JSON」操作，顶部导出按钮走同一归档流程；工具分类也提供导入以恢复工具引用与分组。智能体、技能、流程保留原 VFS 单项／批量删除操作。提示词、MCP、连接及自定义服务商的列表删除通过宿主 `EditorHostContext.requestDelete` 调用共享确认界面与应用命令，无需打开编辑器。模型抽屉菜单提供设置、导出和删除，内置与自定义服务商使用同一关联影响确认：同时删除关联连接，智能体与连接独立，因此保留智能体；指定已删除连接的会话和流程需要重新选择。内置服务商沿用底层删除标记，重启后不会自动恢复；删除全局默认连接时清空默认设置，不自动选择替代连接。不同类别允许同名抽屉，「全部」视图用小型类别说明区分，不增加目录层级。

## 路由与存储

规范地址为 `#/toolbox/<encodeURIComponent(资源路径)>`，资源路径带 `/agents`、`/skills`、`/flows`、`/prompts`、`/mcp`、`/tools`、`/providers` 或 `/connections` 前缀。例如 `/agents/default/example.agent`。旧 `#/agents`、`#/skills`、`#/flows` 链接与导航请求会转换到工具箱，保持原文件路径。旧 `#/settings/providers`、`#/settings/connections`、`#/settings/mcp-servers`、`#/settings/system-prompts` 及携带 anchor 的设置导航请求重定向到工具箱分类或具体条目。

`app-core/configuration` 管理资源操作、分组存储与只读目录；后端用 `createFileSystemView` 组合已有资源源，`ToolboxWorkbench` 仅消费准备好的视图与导航数据。适配层向编辑器传回原始路径/实体 ID 和所属文件系统；原有智能体、技能、流程、提示词及 MCP 存储无需迁移。提示词、MCP、工具、Provider 和 Connection 使用只读内存投影，配置修改仍经过管理服务；投影不包含模型服务商凭据。`app-core/configuration/skills-files.ts` 的 `SkillsEngine` 提供后端拥有的可挂载根目录。`/drawers/*`、`/model-groups/*` 和 `/tool-groups/*` 仅是 UI 抽屉，不改变存储目录或文件身份。

自定义抽屉名称、资源归属及默认分组调整持久化在 `/etc/ui/toolbox-drawers.json`，Web 和 Tauri 共用 VFS 读写。资源重命名时同步更新归属；保存失败不更新内存分组，新建资源的分组保存失败会回滚本次新建资源。

工具目录仅向 UI 暴露 `listTools`、定义及元信息，不暴露调用入口。目录中的启用状态不代表当前会话已获授权；实际可用性仍由宿主、项目权限及运行时决定。

## JSON 交换

`itookit.toolbox` v1 归档包含所选资源的 `kind` 与 `data`。选择抽屉会导出其条目；服务商抽屉包含配置及连接，工具抽屉包含工具引用。条目的可选 `drawer` 字段保存抽屉名，顶层可选 `drawers` 保存选中的抽屉（包括空抽屉）。导入按类别复用同名抽屉，新增资源重映射后的 ID 归入原抽屉；旧版无分组归档仍兼容。智能体、技能、流程、提示词、MCP、Provider 和 Connection 导入为新 ID，保留原资源；流程按草稿保存，允许继续编辑未完成的草稿。MCP 副本初始断开且不自动连接，已发现能力由重新连接后获取。

工具条目是描述与来源引用，导入只解析当前已存在的工具；缺少来源则在写入其他资源前报错。定义和抽屉组织支持往返，不等于运行状态或原始 ID 的原地恢复。导入总是为可编辑定义生成新 ID；MCP 运行状态与发现的能力由重连获取，工具实现不会包含在 JSON 中。历史目录生成的长抽屉名在导入时完整保留。归档内同时选中的 Provider → Connection → Agent 引用映射到新 ID；未选中资源及其他外部引用（工具 ID、其他智能体等）保留原值。此格式用于定义交换，不是包含全部依赖、运行记录和凭据迁移的安装包；MCP 配置导出会包含其配置字段，应按配置文件保管。

跨类型用途分组、收藏和完整依赖迁移尚未实现。

## 共享系统提示词

- 提示词保存于原有 Agents 文件系统的 `/system-prompts/<id>.sp`。工具箱通过只读目录投影显示 `/prompts/<id>`，编辑与删除调用提示词管理服务；不复制存储，也不把业务策略加入 vfs-ui。
- Agent 的 `config.systemPromptId` 保存共享引用，编辑器展示只读预览；`config.systemPrompt` 为专属补充指令，追加在共享内容之后。取消引用仅移除 ID，保留补充指令。新安装的内置 Agent 引用独立种入的提示词。
- 「编辑共享提示词」跳转工具箱单项表单；修改在后续运行中生效。「另存为副本」创建新提示词并切换当前 Agent 的引用，保留其他 Agent 和原提示词。快捷 Prompt 运行时合并共享预设与 Agent 自有项，同名自有项优先。
- 删除确认说明引用影响；Agent 和 Flow 保留失效引用，编辑器显示缺失项，执行时明确报错。内置提示词的删除标记防止默认数据同步重新创建；显式恢复对应内置 Agent 时补回缺失的提示词，保留仍存在的共享内容。
- 导出 Agent 或 Flow 自动包含直接引用的提示词，导入创建独立资源并重映射 Agent 配置、Flow 默认与节点配置中的提示词 ID；提示词的段落和快捷预设保留。抽屉名和分组仍使用统一工具箱归档。
- 保存与外部 VFS 修改均刷新提示词缓存；已提交运行使用原有执行快照。


## 图片文字识别（OCR）

- ChatInput 的 Settings 面板可直接选择 OCR 连接，修改立即保存；识别提示词仅提供编辑入口；「工具箱 → 模型 → 文字识别设置」与聊天图片附件旁的连接按钮复用相同表单。识别提示词沿用已保存的引用，不提供选择器；编辑按钮直接打开当前提示词。可跳转模型管理。配置属于应用，独立于 Session 与聊天默认连接；首次使用未选择连接时先打开配置，取消不会发送图片。
- 选择连接时检查启用状态、凭据及连接已配置层级模型的 `supportsVision` 声明；按 `fast → standard → optimal` 选择第一个支持图片输入的模型，跳过未配置、失效或非视觉模型；不使用连接层级之外的提供商模型或隐式首模型。这里的最低指层级顺序，不按模型价格排序。下拉列表与附件标签显示实际模型和层级。本地 Codex 连接无需 API Key。每次识别前重新校验，传入明确的模型 ID，避免切换聊天模型影响 OCR。
- `app-core/src/configuration/ocr-service.ts` 保存配置到 `/etc/llm/ocr.json`，首次初始化将 `image-to-markdown` 提示词写入已有提示词库；已有内容不会覆盖。后续按引用读取提示词，多段内容保留。删除引用的连接、提供商或提示词时提示 OCR 影响；保留失效引用，失效连接需要用户重新选择，不自动换模型。已删除提示词仅在用户显式点击编辑时补回默认内容，正常识别和启动不会自动恢复。
- `app-shell/src/configuration/ocr-controls.ts` 负责配置、导航与删除提示；`ui-common` 的 `OcrControls` 定义识别、配置读取与保存、配置导航、标签及订阅接口；`OcrSettingsForm` 复用字段渲染并处理即时保存和失败提示。llm-ui 消费该接口，保留缩图与识别结果审阅，不选择提供商或读写应用配置。Web/Tauri 由相同 bootstrap 装配。
- 图片长边超过 2000 像素时尝试缩小，再由视觉模型生成 Markdown，最多返回 4096 tokens。单图可以修改、插入并保留或移除图片；批量顺序识别，失败时停止并显示错误，保留未完成图片及已成功提取的文字。
- 回归覆盖持久化、缺失或禁用连接、非视觉模型、共享提示词更新、取消配置、删除影响、批量失败与编辑器销毁。见 `backend/app-core/tests/ocr-service.test.ts`、`ui/app-shell/tests/ocr-controls.test.ts`。


## 聊天输入设置

- 常用设置按「对话」「图片文字识别」分组，控制项沿用原来的会话保存接口。识别连接是全局设置；识别提示词通过编辑按钮维护，修改连接不会改动提示词引用。
- 「高级设置」默认折叠，包含本会话补充说明、完整回复显示方式和流程/分支参数。保留既有值和运行行为，减少常用面板的信息量。
- ChatInput 设置不再显示 Skills 列表与工具授权按钮；`/skills` 显式打开独立技能管理对话框，仍订阅会话目录变化。智能体/Flow 的授权配置仍在原工具箱资源编辑器中。

### 批量操作的机制与策略边界

`vfs-ui` 的 `createSelectionOperation` 统一选择操作的去重、确认、顺序执行、取消与成功回调，`createDeleteOperation` 保证先删除资源再删除容器，`createMoveOperation` 接收宿主定义的目的地。文件操作与工具箱操作复用执行机制。

`app-shell/src/toolbox/ToolboxDeletion.ts` 从完整资源目录展开抽屉，生成删除计划并过滤已由 Provider 级联删除的连接；`ToolboxWorkbench` 仅注册动作与完成后的刷新。`ConfigurationDeletionDialog.requestResult` 明确返回 `completed` / `cancelled`，不通过资源是否存在猜测用户是否取消；原有编辑器 `request` 保持 void 接口兼容。`DrawerActions` 的归属移动通过公共移动机制调用抽屉服务，具体分组规则仍由宿主负责。

## 导航数据装配边界

`ApplicationBackend.toolboxView()` 不接受浏览器文件系统。后端创建技能文件系统与资源目录，读取抽屉设置，装配默认工具分类，返回 `ToolboxView.initial`（目录节点、条目、资源说明和需要加载的目录）及实时能力端口。首次展示不再逐目录 HTTP 读取，不经 SSE 回调前端读取技能。刷新由 `ToolboxResources.navigation()` 一次准备新数据；前端不编排 inventory 刷新、抽屉初始化、说明查询和分组扫描。

`navigation()` 会重建分组和资源清单，在应用能力描述中按异步刷新操作处理，复用配置域失效机制，
在回复前同步 `ToolboxDrawers` 和 `ToolboxInventory` 快照。不依赖额外配置变更事件，也不作为纯查询批处理；
普通只读查询仍保留原有行为。传输机制不识别工具箱名称或分组规则。

`browser/directory-snapshot.ts` 只实现通用的一次性元数据消费：事件、版本变化或显式读取条件不匹配时回到实时端口；它与普通工作区的首层导航共用，不能当作长期业务缓存。工具箱是配置资源目录，关闭 Git 忽略检查；普通项目文件浏览仍遵循原有忽略策略。

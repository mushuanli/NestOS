# 数字分身扫描器与共享空间

数字分身保存知识与证据，扫描器定义怎样获取候选知识。界面保留一个“数字分身”入口，扫描器与运行记录放在二级页；工具箱继续管理 Agent、Flow 和连接，不新增自动化系统或扫描 DSL。

## 当前使用方式

一条规则由“何时触发、动作与来源、结果与知识接纳”组成。定时是触发方式，采集是动作，界面不把它们拆成独立系统。扫描器与运行记录继续使用现有二级页面。每张扫描器卡片直接显示最近一次运行的时间、状态、耗时、采集数量及具体错误，展开后显示按该扫描器 ID 过滤、按创建时间倒序的最近 5 次运行，并可打开运行详情；后台刷新保留日志展开状态。

1. **何时触发**：手动、定时间隔、来源变化（轮询）或应用事件（授权接口）。来源变化仍按配置间隔检查已有材料，不宣称为实时文件监听；采集动作可用手动、定时、应用事件。
2. **动作与来源**：直接选择已注册、启用并有固定版本的 Tool，按其参数 Schema 填写配置即可，无需创建 Flow。工具负责业务采集、资源格式和授权文件写入；资源类型、账号连接 ID 和保存目录由工具参数声明，核心不按邮件或厂商分支。当前直接采集目录提供只读或本地副作用工具；外部副作用工具、未提供此目录的 MCP 工具继续通过原授权入口使用。多步骤采集仍可选已发布的静态 Tool / Transform / Return Flow。
3. **结果与知识接纳**：选择“仅采集并保存材料”时不要求模型连接，不创建提取 job，也不消耗模型 token；来源文件由工具写入，知识保持不变。选择“提取知识”时，采集后按显式 include / exclude 范围发现材料、检查内容版本并提取；已有文件、直接文本或上传快照也可独立作为来源。
4. 新建表单默认手动、关闭自动接纳。运行后在“运行记录 → 本次新增结果”审核候选知识。已有规则保留原设置；同一次规则匹配中，项目视图与普通工作区指向同一本地文件时只选择一个来源；相同来源内容不会再次调用提取模型，来源变化或删除使旧证据失效。

直接文本和上传 UTF-8 文本保存为空间内快照，最多 128 KiB；工作区文件沿用既有文件授权。URL 通过已有工具采集，不在扫描器里增加另一套网络抓取。输出格式和目标内子目录由 Tool 参数及实现约定，不要求用户额外创建包装 Flow。

直接 Tool 的 `collection.destination` 可显式选择应用文件工作区（emails / notes / home）。运行时从已保存、仍有效的扫描运行读取该授权，将对应 `/home/admin/<workspace>` 挂为工具的 `/workspace`，相对路径在该目标内解析；不授予项目、其他工作区或宿主物理根目录。每次文件访问复验规则版本、启用状态、空间权限与扫描租约。未配置时保持旧项目上下文；静态 Flow 不接受此目标字段。UI 的“保存位置”独立于 Tool 参数，计划和运行记录显示目标，工具参数不能扩大目标授权。切换位置不自动迁移正文或工具检查点。应用目录始终相对当前宿主数据根映射，不硬编码部署路径。

## 应用事件与恢复

宿主或已认证客户端调用 `DigitalTwinService.triggerScanPlan(planId, eventId)`；只接受启用且触发方式为 event 的规则，事件 ID 必须非空且不超过 256 字符。该端口经显式 RPC 能力开放，仍逐次检查空间写权限；不提供匿名 HTTP 回调或从事件参数选择用户身份。

事件 ID 按规则隔离，以摘要保存回执；事件回执与入队在同一 SeqFile 事务完成。重复事件返回原 runId。尚未开始的事件合并到同一个排队运行；已有运行进行时，新事件创建一个后续运行，避免漏掉当前执行快照之后的变化。回执跨重启保留，队列满或校验失败不记录成功回执。自动调度只检查 interval / changes，event 不会被计时器自动执行。在线后台负责消费队列。

“立即更新”对仅采集模式跳过入队前的来源索引同步，先写入现有持久队列，再由后台 worker 执行；知识提取模式保留来源同步。入队准备日志记录计划身份、同步是否跳过、耗时及安全错误分类，不记录参数或材料正文。

运行记录仍使用原队列、租约和 fence，不增加事件总线。重启后沿用原中断与副作用核对语义，不把未知结果当作未执行并自动重发。采集能力取得前后都复验授权，取消复用 Kernel Task 与 Effect 的停止确认。批量写入或删除应由工具按稳定来源 ID、版本和完整范围核对；不完整或失败的采集不能宣称远端记录已删除。

采集结果可携带通用 `collection: {version: 1, complete: boolean, processed: number, batchCount?: number}` 回执，直接 Tool 和采集 Flow 共用；核心只验证并持久化完成标识、非负工作量与可选本批归档数量（含 0，旧记录缺失时不补记为 0），不读取厂商游标或业务记录。未完成批次仍是成功保存的运行，界面显示等待继续；interval 计划通过同一 lease/fence 事务把下一次安排提前至约 15 秒后，完成后恢复原间隔。manual/event 不自动升级为定时，保留原触发授权。工具自行保存续传游标、幂等回执及归档身份，取消、授权撤销、API 或文件失败仍按原失败语义处理。

## 自定义执行器的结果

Agent 或 Flow 应返回以下 JSON；quote 必须是本次材料中的精确片段，单次最多接纳 10 项。kind 使用既有知识类型，subject 可用 self 表示用户。工作区和用户身份由宿主绑定，模型不能指定知识所属空间。

```json
{
  "candidates": [
    {
      "content": "偏好 TypeScript",
      "kind": "preference",
      "subject": "self",
      "project": "",
      "eventTime": "",
      "quote": "我喜欢 TypeScript。"
    }
  ]
}
```

Agent 默认读取 message.content，Flow 默认读取标准返回节点的 result.content；其他结构可在高级设置填写结果路径。非法 JSON、无效字段或不受材料支持的引文会使此次提取失败，不写入知识。

执行复用已发布目标的独立调用、Kernel Task、取消和回执，保留执行历史。当前文本扫描不支持原生 harness、媒体、动态委派和嵌套独立调用；这些执行不能被当作已完整计量的文本调用接纳。静态 Flow 及其受支持的内联函数仍使用原执行机制。

## 用户自己的数据连接

Node 应用宿主提供 `ToolConnections`：外部包声明连接字段，界面根据字段生成表单，可导入本地授权 JSON；秘密字段只写入，不回传，编辑留空保留。宿主在每个用户的私有 authDir 下创建 `NodeToolConnections`，通过 Tool 工厂 API 注入用户绑定的 `resolve(id,type)`，不开放该方法的 RPC，也不接受模型提供的用户 ID 或凭据路径。共享工具代码和 Flow 定义不共享连接、来源或记忆。组织空间切换不改变认证主体的凭据归属。

已提供独立 [Google 工具包](../../tools/googlecli/README.md) 及其包内采集 Flow 资源（不再作为 NestOS 内置预设）。账号只读授权和每用户导入说明见工具包文档。每次有界完整核对，超过数量限制不发布不完整快照；当前不使用远端增量游标。OAuth 端点与权限由外部包声明，通用宿主提供每用户授权交互；平台边界及尚未实现的 ResourceTarget 见[外部功能扩展](function-extensions.md)。

界面将触发、动作与来源、结果与知识接纳分开；Tool 参数按其 Schema 生成，Flow 参数复用公开表单，模型预算放入折叠项。连接、工具与密钥不作为模型普通参数。采集失败区分授权、API 权限、数量/格式、传输与文件写入阶段，日志只保存关联身份、阶段、分类、数量及耗时。

## 空间与共享

页面顶部可切换宿主提供的个人 / 组织空间；切换只影响当前视图，未保存的扫描器草稿会阻止切换。每个空间独立保存来源、知识、扫描器和额度；组织空间不自动创建个人默认扫描规则，材料范围须显式配置。只读空间允许查看，后端也拒绝修改知识、扫描配置和预算。

宿主用 `ApplicationRuntimeOptions.digitalTwinWorkspace` 绑定主空间，用 `digitalTwinWorkspaces` 提供额外空间。绑定包含 twinId、ownerId、name、kind、readOnly、authorize(access)，可用 fs 注入共享存储。ownerId 是稳定空间归属；authorize 由服务端按当前认证主体检查成员与读写权限，不能取自模型或客户端参数。

同一组织的成员使用相同 twinId、ownerId 和共享存储。授权在服务访问、预留、模型发送及结果提交阶段复验；共享知识不自动共享文件、工具权限或模型密钥。发布目标和执行连接沿用当前运行时已授权的配置，组织成员目录及登录映射仍由宿主负责，当前没有另建成员管理或复杂角色系统。

## 额度与用量

费用模式保持自带密钥 / 宿主绑定组织额度，不做平台代付或支付。累计预算、UTC 自然月额度和可选单次运行上限同时生效；累计不限额不跳过其他上限，0 拒绝新调用。知识提取需要在通用设置配置有效模型连接；仅采集模式不需要模型连接，纯计算的知识提取 Flow 仍使用该来源绑定。

自定义 Agent / Flow 每个提取任务缺省预留 50,000 token；设置单次上限时，从剩余运行额度中最多预留 50,000 token，整个扫描不能超出该上限。每次实际模型尝试发送前，按请求大小与输出上限扣减该任务预付范围，同一 attempt 重复授权不重复扣减。用量按子 Session 的模型任务汇总；全部有报告才记为实际报告，否则使用保守估算，父调用不重复计费。纯转换 Flow 可确定没有模型调用时结算为 0。

扫描器还可配置 `maxOutputTokens`（128–8192；空值保持原默认），约束每次模型回答；内置提取按该值预留输出，自定义 Agent/Flow 在发送前取自身上限与扫描器上限中的较小值。它不代替整个运行的 token 额度。界面展示累计与月度剩余额度的较小值，以及已用、预留和待结算状态。

月度预留、job 和累计预算同事务提交；结算归原月份，重复结算不重复消费。失败 / 取消后未知用量保持 pending，不能显示为免费。token 账本不代表供应商实际金额，也不覆盖外部工具自身收费；不提供成员分摊、支付、价格维护或媒体账单。

当前 schema 1/layout 8；已知 layout 2/3/4/5/6/7 保留数据并升级元数据，旧客户端不得忽略执行器或额度。未知布局拒绝打开，不清空重建。

# 数字分身：规则驱动设计与实施

## 产品目标

数字分身是个人信息平台的持续更新视图。自动发现所有已登记项目的文本文档、原生会话和可读取的远程 harness 会话，用户通过扫描规则控制范围，不维护逐个来源的授权清单。

流程：项目目录与会话目录 → 规则筛选 → 周期更新 → 模型提取 → 分身画像、记忆与目标。

五个主页面保持总览、画像、记忆、目标、来源与扫描。扫描页默认进入“扫描规则”，另有“扫描状态”和只读“来源明细”；工具箱继续配置模型、Agent 与 Flow。

## 用户配置

全局设置只有分析模型、累计 token 预算、暂停分析、允许授权会话使用，以及全局排除。模型和预算不在每条新规则中重复配置。

规则配置名称、启停、白名单、黑名单、更新周期和提取类型。默认周期 30 分钟、全部类型。应用启动和 CLI 扫描启动会初始化存储，无需先打开页面。在有可用默认模型且没有自动规则时，首次建立一个全范围默认规则；此初始化幂等，用户删除规则后不会再次自动创建。

新规则保存即声明其扫描范围，无需逐个添加来源或重复勾选授权。匹配预览只列资源，不读取正文或调用模型，也不新增来源记录。

### 匹配语法

白名单和黑名单分别维护，每行一条；空白和以 `#` 开头的注释被忽略。

```text
# 白名单示例；留空表示全部受支持资源
project:Alpha
file:**/*.md
file:docs/
session:native/**
session:harness/codex/**

# 黑名单示例
project:Archived*
file:**/drafts/**
session:harness/codex/temporary-*
```

| 前缀 | 匹配对象 |
| --- | --- |
| project: | 项目稳定标识或名称；命中该项目的文档和会话 |
| file: | 相对项目根目录的文件路径，使用 `/`，没有开头 `/` |
| session:native/ | 原生会话稳定标识 |
| session:harness/ | harness profile 标识 / 会话稳定标识 |

支持 `*`（不跨目录）、`**`（跨目录）、`?`（单个非 `/` 字符）、目录末尾 `/` 和整行注释。`**/*.md` 同时匹配根目录和子目录。采用大小写敏感匹配；这是借鉴 gitignore 的受限语法，不支持 `!`、字符集合、花括号或转义，避免白名单/黑名单再引入反转顺序。

一条规则内：白名单为空或任一命中，且黑名单没有命中，即允许扫描。多个规则取并集；某条规则的黑名单不会阻止其他规则允许该资源。全局排除对所有规则生效。名称规则随项目改名重新匹配，稳定 ID 规则保持身份；预览显示项目名称和 ID，便于检查范围。

内置跳过隐藏路径、`node_modules`、私密标签和受保护文件，不把配置、分身产物和内部执行快照当作个人资料。

## 自动更新

项目服务负责项目身份与目录授权，分身只通过其公开接口枚举和读取。项目目录读取使用 `ProjectService.openFiles`，涵盖应用内、已登记宿主目录和远程项目；不直接读取 IndexedDB/SQLite 或任意宿主磁盘。

原生会话通过 SessionRepository 和当前分支 RoundLog 读取，未归属项目的原生会话归入 `@unassigned`。内部 `twin-analysis-*` 会话不参与发现。正在运行、内部 exposure、合并历史或不完整历史保持不可用，不猜测缺失正文。

远程 harness 通过已有项目客户端枚举有历史能力的 profile，分页读取活动及归档会话。读取历史不恢复执行。仅提取可见 userMessage/agentMessage 文本；系统提示、推理、工具输出和审批内容不进入来源正文。会话正在执行或历史不可读取时等待下次周期。

| 来源变化 | 处理 |
| --- | --- |
| 新项目、新文件、新会话 | 下一次到期发现，匹配规则后自动加入 |
| 正文变化 | 内容 hash/来源代次变化，旧证据退出有效分身，从新版本重新提取 |
| 同路径替换 | 可观测原生身份或 hash 变化时建立新代次，不沿用旧证据 |
| 删除 | 仅在完整成功枚举该范围或确认来源不存在后判定；依赖该来源的旧信息失效 |
| 离线或枚举失败 | 标为不可访问并显示诊断，不判定删除，恢复后重新读取 |
| 规则停用、删除或范围变化 | 按所有仍启用规则重算来源；没有规则允许的来源停止参与分身 |
| 全局排除 | 所有规则都停止使用该来源，拒绝在途旧结果 |
| 移动或改名 | 原生会话稳定 ID 可沿用；文件没有跨移动稳定身份时按旧路径退出、新路径发现处理 |

文件到期更新校验正文 hash，避免仅靠时间戳漏掉保留元数据的内容替换；普通界面/使用核对可用元数据跳过重复正文读取。未变化版本不重复模型提取。文件的原生身份仍由目录绑定、路径和可观测创建时间组成，不宣称可识别所有保留元数据且同内容的宿主替换。原生与 harness 会话周期读取可见历史并比对 hash；当前不实现跨轮编辑的精细片段依赖。

删除、替换、排除后，自动信息保留必要历史但不再计入有效画像或模型检索。用户手工记录与纠正为独立陈述，不随原始来源失效。普通自身信息自动生效；其他人物归属保持待确认。模型提取仍可能出错，用户可纠正、争议、拒绝或遗忘；自动生效不代表完成了语义正确性验证。

## 调度与存储

复用现有扫描队列和 Kernel 提取任务，默认串行。每 15 秒检查到期规则，按配置周期发现与处理资源；错过的触发合并补跑。相同来源版本、模型目的地和提取类型复用进度，不因规则重叠重复提取。

运行时在线才调度：浏览器/桌面关闭、休眠或后台节流会延迟更新。CLI `twin watch` 可作为持续在线进程；未安装独立操作系统服务。

保留的内部机制只有必要的来源身份/hash、提取进度、执行引用、预算记账和扫描宿主租约。规则编辑、停用、全局排除、模型切换和删除均在模型发送及结果提交时重新校验，阻止旧任务写回。预算预留和实际费用原子记账；未知模型用量不按免费释放。

仍使用 VFS 公开 SeqFile 事务，不新建数据库表。四个文件位于 `/var/lib/digital-twin/personal/`：

| 文件 | 内容 |
| --- | --- |
| authority.seq | 分身身份、遗忘代次、tombstone 和清理状态 |
| knowledge.seq | 所有领域记录的版本链与当前指针，包括记忆、来源、规则、运行、授权与设置 |
| processing.seq | 提交/遗忘/清理的操作回执 |
| indexes.seq | 固定分页索引与族索引 |

实际记录族的文件归属以 [SeqTwinStore](../../packages/app-core/src/digital-twin/seq-twin-store.ts) 为准。当前 schema 1/layout 4；已知 layout 2/3 事务升级元数据并保留身份、记忆和遗忘状态，阻断旧客户端忽略规则授权。未知布局保持拒绝，不清空重建。

旧指定来源计划与 CLI 命令保留兼容，旧计划保持原范围；新默认规则按当前规则设计覆盖所有项目。界面编辑旧计划后转换为自动规则。新规则通过 `rules` 标识，持久 sourceIds 为空，每次运行从自动来源索引解析其范围。

## 实现与边界

| 模块 | 职责 |
| --- | --- |
| [scan-rules.ts](../../packages/app-core/src/digital-twin/scan-rules.ts) | 类型前缀、glob、规则验证与匹配 |
| [project-catalog.ts](../../packages/app-core/src/digital-twin/project-catalog.ts) | 项目文档和原生会话发现、完整范围标记 |
| [harness-reader.ts](../../packages/app-core/src/digital-twin/harness-reader.ts) | harness 分页发现与可见历史读取 |
| [source-reader.ts](../../packages/app-core/src/digital-twin/source-reader.ts) | 公开服务读取文档/会话，正文 hash 和元数据探测 |
| [source-index.ts](../../packages/app-core/src/digital-twin/source-index.ts) | 自动来源索引、并集/全局排除、完整性与删除核对 |
| [scans.ts](../../packages/app-core/src/digital-twin/scans.ts) | 规则与运行编排，复用现有队列/宿主租约 |
| [service.ts](../../packages/app-core/src/digital-twin/service.ts) | 宿主用例、全局配置与授权消费 |
| [scan-view.ts](../../packages/app-shell/src/digital-twin/scan-view.ts) | 规则表单、匹配预览、运行状态与来源明细 |

公开新入口为 `saveScanRule`、`previewScanRule`；启停、删除与立即扫描沿用 `setScanPlanEnabled/removeScanPlan/runScanPlan`。reader 的 `discover/probe` 是平台无关端口；数据库 driver 不含分身业务。

自动读取受支持的文本文档；PDF、Office、图片等尚未接入正文解析。每来源最大 1 MiB，原生当前分支最大 2000 轮；harness 分页有游标循环与字节上界。最多 10000 来源、50 规则、100 待结束运行、500 当前记忆，运行/检查点及其他记录族各有 10000 上界；页面来源明细展示前 200 条，不限制后台处理这 200 条之外的来源。

消费继续接入本地原生 Chat/Agent 的会话授权与模型发送门禁；规则授予分析范围，不自动授予所有会话消费权限。目标只关联既有执行，不自动启动行动。共享 profile 的租约依赖事务和可比较时钟；真实跨时钟、多端同步、外部备份恢复和完整进程崩溃矩阵不在本次验收内。

## 模型提取协议与诊断

提取任务显式设置 thinking=false、maxTokens=8192、stream=false，避免兼容服务默认思考耗尽正文额度。通过提示词约束 JSON 并严格校验字段与原文证据，不向不支持 json_object 的协议发送该参数。响应日志区分正文和思考字符数，保留结束原因及包含缓存输入的模型用量；解析失败报告候选序号与具体问题，不输出私有正文。达到输出上限明确报告截断。

应用通过 pnpm patchedDependencies 接入驱动修复，补丁随锁文件安装，不需要直接修改 node_modules 或提前发布 npm 包。

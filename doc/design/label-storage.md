# 标签存储与查询

NestOS 内部文件系统支持标签。宿主工作目录、动态本地挂载、CLI/Tauri 授权的外部目录均关闭 tags 能力：不显示标签，不接受标签修改，不参与设置页统计。关闭能力不会删除历史 sidecar 数据。

## 数据边界

- `/etc/tags.seq`：标签定义，key 为 `tag/<id>`，value 保存名称、颜色、描述；`schema=1`。引用数量是查询结果，不持久化。
- SQLite `meta_ext.tags` 与 `meta_tags(path, tag)`：文件标签及关联索引，在同一数据库事务内更新。目录重命名同步迁移关联，递归删除清理子树关联。
- IndexedDB `nodes.tags` 与 `tags` store：标签修改、重命名同步更新关联索引。
- 内存后端提供同样的查询契约。

标签定义首次修改时，将旧 `/etc/tags.json` 定义在 SeqFile 事务内迁入；查询不会主动创建文件。迁移完成后只使用 tags.seq，旧文件保留。未使用的标签定义不会因引用数为零而消失。

## 查询路径

`IStorageBackend.listTagEntries → VFSEngine → TagOps → FileSystemView → SettingsService`。

查询仅访问标签关联记录，不调用目录遍历、逐文件 stat 或文件内容读取。作用域转换会过滤授权根之外的路径及被其他挂载遮蔽的路径；外部目录直接禁用该能力。`getAllTags()` 返回标签与引用数，`walkByTag()` 保留分页及提前停止语义。

启动只读取标签定义，不统计工作区；打开标签页时查询内部索引。普通文件变更不触发标签统计。加载失败显示错误，不再只写控制台后表现为空白。

## 一致性与扩展边界

不把全系统文件关联复制到一个中央 SeqFile：不同工作区属于不同数据库，中央副本无法与所有文件变更在一个事务内提交。保留原生索引可避免这一双写问题。

当前查询成本与标签关联条数相关，不再与工作区总文件数、目录深度或文件大小相关。当前接口仍返回范围内关联集合；关联量很大时可进一步增加后端分组计数、按标签游标分页，避免全量关联传输。

上述一致性覆盖应用通过文件系统接口执行的操作。绕过应用直接修改宿主文件、旧版本遗留损坏、跨多个工作区删除一个标签，都不是单数据库原子事务；失败应保留定义并报告，重试继续清理。不能把单个 tags.seq 视为自动保证高可用或跨存储事务的机制。
